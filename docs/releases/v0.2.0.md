## Installing is now four steps

Copy the resource, run one SQL file, fill in three things in
`config/server.lua`, and run the setup command the console prints. No convars,
no Node service, and **no cron job**.

Discord role sync moved out of the (never-built) gateway and into FXServer
itself (ADR-010). It refreshes the whole guild on a timer and each player as
they connect. You need a Discord bot with the **Server Members** privileged
intent; you no longer need to deploy anything alongside the server.

Full instructions: `docs/installation.sv.md` in the bundle.

## ⚠️ If you already installed v0.1.0, read this

**v0.1.0's setup mapped _every_ Discord role you held to the `admin` group.**

If you ran the v0.1.0 bootstrap SQL and you hold a role that ordinary members
also hold — `@Member`, `@Whitelisted`, `@Booster` — then everyone with that role
is currently a FredPD administrator. That grants `admin.permissions.edit` and
`admin.audit.view`: they can read the audit log, which is a list of Discord ids,
and they can grant further access.

Upgrading does not fix existing rows. Check what is mapped:

```sql
SELECT discord_role_id, discord_role_name, group_key, agency_id
  FROM fpd_role_map
 WHERE group_key = 'admin';
```

Delete anything that should not be there:

```sql
DELETE FROM fpd_role_map WHERE group_key = 'admin' AND discord_role_id = '<role id>';
```

Setup in v0.2.0 takes one named role, and only one you hold yourself.

**Also stop any cron job** that runs `UPDATE fpd_discord_members SET synced_at =
NOW()`. The v0.1.0 installation guide suggested one as a stopgap. It forges the
freshness signal the outage policy reads: with it running, a Discord outage
looks like a healthy sync and revoked roles stay in effect. The sync now writes
that column only alongside a role list Discord actually returned.

## Also in this release

- A complete guild walk clears anyone it did not see, so removal from Discord
  takes effect for a connected officer instead of waiting for them to log out.
- A member-level 404 is verified against the guild before it is believed — a
  kicked bot no longer looks like a department where nobody has any roles.
- The first officer is bound to the character they set up on (spec 4.1).
- The schema ships as one baseline migration, `0001_fredpd.sql` (ADR-009).
- The release bundle now carries the Swedish installation guide and the
  in-character service manual.

## Known gaps

- **Records, Dispatch and Comms appear in the rail with no page behind them.**
  Anyone mapped to `patrol` or `dispatch` will find a blank pane. Those modules
  are M2–M4.
- The fleet is still edited in SQL; there is no in-game fleet editor yet.
- Evidence uploads need the gateway's media service, which is not built.
  External links work.
- None of this has run on a live FiveM server yet. The logic is covered by
  tests; the parts that call game natives are not.
